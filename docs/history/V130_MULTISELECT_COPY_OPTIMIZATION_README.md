# V130 多选与复制可靠性优化

版本：`0.1.130`

本版针对项目右键菜单的多选体验、批量复制可靠性和相关状态管理进行了集中整理。

## 1. 多选改为明确的“使用多选”模式

项目右键菜单中移除了：

- `取消选择此项`
- `清除多选`

新增统一入口：`使用多选`。

操作方式：

1. 右键任意项目，点击 `使用多选`。
2. 进入多选模式后，直接左键项目即可选择 / 取消选择。
3. 已选择项目会显示明确的勾选状态。
4. 多选期间暂停项目原本的单击 / 双击动作，避免“想选择项目却触发复制或打开”。
5. 多选期间暂停项目排序拖动，避免选择动作误触发拖拽。
6. 在已选项目上右键时，复制、移动、删除等批量命令会针对当前整组已选项目执行。
7. 顶部会显示 `已选 N · 完成`，点击“完成”即可退出多选并恢复项目原本点击行为；Esc 也可以退出。
8. `选中本页全部` 会自动进入多选模式。

多选状态属于临时 UI 状态，不写入配置文件；切换配置、目录或恢复数据时不会留下“幽灵多选状态”。

## 2. 复制逻辑可靠性整理

新增统一复制模块 `src/lib/itemCopy.ts`，项目复制、粘贴、创建副本、复制到其他子目录均复用同一套复制规则。

主要处理：

- 复制时创建独立快照，`browserRoute` 与 `multiAccountBatch` 不再和源项目共享嵌套对象引用。
- 每次粘贴 / 复制都会生成新的项目 ID，避免源项目与副本 ID 冲突。
- 多账号批次 ID 会重新映射：同一原批次的一组项目在副本中仍属于同一个新批次，但不会继续指向原批次。
- 再次粘贴会生成另一套新批次 ID，避免两次粘贴互相串联。
- V129 的“单击动作 / 双击动作”和网站浏览器路由会完整保留。
- 副本的启动次数、最后启动时间会重置，不把源项目使用统计复制过去。
- 批量“复制到子目录”由逐项目多次状态更新改成一次原子状态更新，减少大量项目复制时的重复渲染和中间状态。
- 输入项目 ID 会先去重，避免异常调用导致同一项目重复复制。
- 项目剪贴板与父/子目录导航剪贴板继续保持互斥，降低粘贴错类型的风险。

## 3. 代码优化

- `collectItemsByIds` 一次扫描项目树获取全部待复制项目，代替批量复制时反复全树查找。
- 多选生命周期集中为 `beginMultiSelect / finishMultiSelect`，减少组件各自维护零散选择状态。
- `ItemCard` 的选择、点击动作、拖动行为在多选模式下使用统一分支，减少单击 / 双击 / 拖动之间的竞争。
- 顶部完成按钮提供明确退出路径，不再依赖右键菜单里的“清除多选”。
- Rust build guard 与 `scripts/verify-source-fixes.mjs` 已加入 V130 的关键功能守卫，防止后续版本误删多选入口、重新加入旧菜单或绕过统一复制逻辑。

## 4. 兼容性

旧项目无需迁移。未使用多选时，V129 已有的项目单击、双击、复制、打开和自定义浏览器逻辑保持原行为。
