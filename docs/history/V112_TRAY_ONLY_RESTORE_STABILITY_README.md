# v0.1.112 托盘常驻 / 隐藏恢复稳定性修复

本版针对 Windows 托盘模式继续修复三个问题：主窗口不再显示任务栏按钮、长时间隐藏后的状态竞争、关闭到托盘后再次点击托盘偶发恢复成左上角小窗口。

## 1. 主窗口彻底不进入任务栏

- `tauri.conf.json` 主窗口新增 `skipTaskbar: true`。
- Windows 原生扩展样式由 v111 的“强制 `WS_EX_APPWINDOW`”改为“强制 `WS_EX_TOOLWINDOW` 并移除 `WS_EX_APPWINDOW`”。
- 原生贴边线程重新获取主窗口句柄时也保持相同规则，避免贴边动画或隐藏/显示后任务栏按钮重新出现。
- 托盘图标继续保留，应用仍可通过托盘显示主窗口或退出。

## 2. 修复关闭到托盘后点击托盘出现左上角小窗口

v111 的托盘窗口快照只要求大于 `200 x 160`，这意味着隐藏/动画/状态切换期间出现的临时小尺寸也可能被当成正常窗口尺寸保存，下一次托盘恢复就会把这个异常尺寸重新应用。

v112 改为：

- 托盘快照必须至少满足应用真实最小尺寸 `900 x 640`。
- 快照位置必须与当前至少一个显示器相交，否则不覆盖上一份正常快照。
- 没有可用快照时使用安全默认值 `1180 x 880` 并居中，而不是继续沿用异常小窗状态。
- 托盘恢复后增加短时几何校正，防止 Windows / WebView2 在隐藏窗口重新显示后异步覆盖尺寸或位置。
- 每次隐藏/恢复都有恢复代次编号；旧的延迟恢复任务会自动失效，不会在下一次操作后继续改窗口。

## 3. 取消“托盘恢复”和“贴边恢复”同时抢窗口

v111 在真正从托盘恢复后，仍然无条件发送 `edge-force-show`。这会造成：

1. 托盘逻辑恢复保存的尺寸和位置；
2. 贴边逻辑同时尝试恢复自己的历史矩形；
3. 两条路径竞争，最终窗口可能被旧矩形覆盖。

v112 只在“不是托盘隐藏、而是贴边隐藏”时发送 `edge-force-show`。真正的托盘恢复只有一条几何恢复路径。

## 4. 修复“启动项目后隐藏到托盘”绕过 Rust 状态机

之前设置为“启动项目后：隐藏到托盘”时，前端直接执行 `appWindow.hide()`。这不会设置 Rust 的 `TRAY_HIDDEN`，因此窗口虽然看不见，原生贴边线程仍可能继续检测、移动或重新显示它，隐藏时间越长越容易暴露状态问题。

现在前端改为调用 Rust 命令 `hide_main_window_to_tray`，与：

- 点击右上角关闭按钮；
- 托盘菜单“隐藏到托盘”；

共用同一套隐藏逻辑。隐藏期间原生贴边线程会进入托盘休眠状态。

## 5. 关闭按钮逻辑统一

`CloseRequested` 不再复制一套独立的“保存快照 -> 标记托盘 -> hide”代码，而是统一调用 `hide_main_window()`，避免以后修改托盘逻辑时出现两套行为不一致。
