# V127 多账号名称预览 + 子目录自由拖动

版本：`0.1.127`

## 1. 右上角“多账号批量生成”增加名称预览

- 在“网址与命名”区域新增 **生成名称预览**。
- 只显示 1 个示例，固定使用“首个网址 × 首个已选账号”，避免批量账号很多时预览区过长。
- 预览会实时响应：
  - 项目公共前缀
  - 网址标签 / 多网址命名
  - 命名顺序
  - 分隔符
  - 账号别名
  - 是否只保留字母
  - 是否加入浏览器名
- 预览与真正生成项目复用同一套 `buildAccountBaseName` + `buildProjectName` 命名逻辑，降低“预览一个名字，实际生成另一个名字”的风险。
- 未输入网址时显示“请先输入网址”；有网址但未选账号时显示“请先选择一个账号”。

## 2. 子目录支持更自由的上下拖动排序

原先数据层已经有 `reorderDirectories`，V127 对侧栏拖动交互做了补强：

- 子目录整行继续可以直接拖动，不要求必须拖某个小把手。
- 拖动启动距离从 6px 调整为 4px，响应更直接，同时保留一点防误触距离。
- 增加 `DragOverlay`，拖动项目不会被侧栏滚动容器裁切，长列表里拖到上方/下方时更清楚。
- 侧栏列表增加 `flex: 1`、`min-height: 0`、`overflow: auto`，保证长子目录列表仍能滚动拖动。
- 拖动时加入抓取光标、半透明原位置和悬浮阴影反馈。
- `handleDragEnd` 增加索引有效性保护，只有合法的起点/终点才提交排序。
- 保留键盘排序传感器，可继续使用 DnD Kit 的键盘排序能力。

## 3. 回归保护

新增/加强了持久源码守卫：

- 多账号名称预览必须存在，并明确只预览一个名称。
- 子目录侧栏必须保留 `DragOverlay` 与拖动状态处理。
- 子目录拖动列表必须保持可滚动布局。
- App Store 单元测试新增“子目录可向上、向下重新排序”的回归用例。
